# Toolchains e APIs conferidas para as versões (20–21/10/2026)

Resumo do que cada versão usa e onde foi conferido. "Não verificado" marca o que a
documentação não fecha; esses pontos estão sinalizados também nos READMEs das versões.

| Família | O que foi conferido | Fonte | Não verificado |
|---|---|---|---|
| Hailo (02, 03, 12) | Hailo-8/8L: Model Zoo v2.x + DFC 3.x + HailoRT 4.x (`hailo-all`); Hailo-10H: Model Zoo v5.x + DFC 5.x + HailoRT 5.x (`hailo-h10-all`); os pacotes não coexistem. Export Ultralytics `format="hailo", name=...` (INT8, NMS no HailoRT, Linux x86_64). API `VDevice → create_infer_model → configure → create_bindings → run`; saída NMS por classe `[y_min, x_min, y_max, x_max, score]` (hailort.h) | docs.ultralytics.com/integrations/hailo; github.com/hailo-ai/hailo_model_zoo; github.com/hailo-ai/hailort; github.com/hailo-ai/hailo-apps; raspberrypi.com/documentation/computers/ai.html | normalização das coordenadas NMS (implícita); `image_dims` para entrada ≠ 640 no hailomz |
| IMX500 (04) | Export Ultralytics `format="imx"` só para YOLOv8n/YOLO11n, INT8 forçado, NMS embutido, saída `packerOut.zip`; `imx500-package` no Pi gera `network.rpk`; Picamera2: `IMX500(...)` antes de `Picamera2(imx500.camera_num)`, `get_outputs`, `get_input_size`, `convert_inference_coords`, `set_auto_aspect_ratio`; saídas boxes/scores/classes/num em pixels do tensor, ordem xy | docs.ultralytics.com/integrations/sony-imx500; raspberrypi.com/documentation/accessories/ai-camera.html; github.com/raspberrypi/picamera2 e picamera2-examples; pós-processador Sony `pp_od_yolo_ultralytics` | host x86 × ARM64 para o export |
